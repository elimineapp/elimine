# Design

## Context

The Android project still carries Flutter's template launcher icon: one `ic_launcher.png` per density in `android/app/src/main/res/mipmap-*`, referenced as `@mipmap/ic_launcher` in the manifest, with no adaptive icon definition. The minimum Android version is 7.0 (API 24). There is no iOS project yet.

The designer's export is generated by one script, `source/gen.py` (CairoSVG), from two leaf paths and a gradient, and contains:

- `android/res/drawable/`: background, foreground and monochrome layers as vector drawables (108 dp canvas, leaves scaled into the 66 dp safe zone);
- `android/res/mipmap-anydpi-v26/`: `ic_launcher.xml` and `ic_launcher_round.xml` adaptive definitions;
- `android/res/mipmap-*/`: legacy `ic_launcher` and `ic_launcher_round` PNGs, plus PNG copies of the three layers;
- `android/play-store-512.png`, `ios/AppIcon.appiconset/`, `source/icon.svg` and a rounded preview SVG.

## Goals / Non-Goals

**Goals:**
- Crisp adaptive icon with background, foreground and monochrome layers; legacy square and round icons for Android 7.x.
- Sources in the repository, enough to regenerate the resources.

**Non-Goals:**
- iOS icons: there is no iOS project; the iOS icon set is only stored for later.
- A custom splash screen. Android 12+ already shows the launcher icon on its system splash; tuning its background color is a separate change.
- Showing the icon inside the app UI.
- Play Store listing assets beyond keeping the 512 px image.

## Decisions

**Use the designer's vector drawable layers as they are.**
The leaves are two paths and the background one gradient, so vector drawables stay small and sharp at any launcher size, unlike density PNGs. Gradients in vector drawables need API 24, which is the minimum version.
Alternative: rasterizing the layers with `flutter_launcher_icons` (tried with the previous artwork). It adds a dependency and produces 15 PNGs where 3 small XML files do.

**Copy only the resources that are referenced.**
The adaptive definitions, the three vector layers and the legacy `ic_launcher`/`ic_launcher_round` PNGs go into `android/app/src/main/res/`. The PNG copies of the layers are left out: nothing references them once the vector layers exist.

**Add `android:roundIcon` to the manifest.**
Launchers on Android 7.1 that ask for round icons get the designer's round version instead of masking the square one.

**Keep the sources in `design/icon/`: `source/` (master SVG, preview, `gen.py`), `android/play-store-512.png` and `ios/AppIcon.appiconset/`.**
A top-level `design/` folder makes it clear these are not runtime Flutter assets, so they do not grow the APK. `design/icon/README.md` says what each file is for and how to regenerate with `gen.py` and copy the outputs. The script's `out/` directory is ignored by git.

## Risks / Trade-offs

- [`gen.py` needs CairoSVG and the Cairo library, not installed on the development machine, so regeneration was not run here] → the committed resources are the designer's outputs; the README lists the requirements.
- [The vector background has only the gradient, while the PNG renders also have a soft highlight] → barely visible at launcher sizes; check on the phone.
