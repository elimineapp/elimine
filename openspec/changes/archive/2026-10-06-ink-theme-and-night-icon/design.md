# Design

## Context

`ElimineApp` builds both themes with `ThemeData(colorSchemeSeed: Color(0xFF3F6E5A))`. Flutter turns the seed into a Material 3 "tonal spot" scheme, which tints the neutral palettes (every surface, outline and secondary text) with the seed's green hue. Screens read colors only from `Theme.of(context).colorScheme`, plus the substance palette in `lib/core/appearance.dart`; nothing else in `lib/` or in the Android resources hard-codes a theme color. So the theme can change in one place.

The launcher icon is produced by `design/icon/source/gen.py`: the glyph (two leaf paths) and the background (a linear mint-teal-blue gradient plus a soft white radial highlight) are defined there and written out as the master SVG, Android vector layers and PNGs. The vector background layer has the gradient but not the highlight.

Flutter's `ColorScheme.fromSeed` uses `material_color_utilities` 0.13.0 with the 2021 color spec.

## Goals / Non-Goals

**Goals:**
- Exact, reviewable color values for both themes, reproducible from a script.
- The same Material 3 roles as today (containers, fixed colors, inverse colors), so every widget keeps a sensible default.
- One icon generator run updates every icon file.

**Non-Goals:**
- Dynamic color (wallpaper-based Material You).
- Per-component theme overrides (button shapes, typography). Only colors change.
- Any change to the substance palette or to how screens use theme roles.

## Decisions

### Explicit color schemes, generated once and committed

The two `ColorScheme`s are written out as constants in a new `lib/app/theme.dart`, generated by a script, `design/theme/gen.py`. `ElimineApp` uses `ThemeData(colorScheme: inkLight)` and `ThemeData(colorScheme: inkDark)`.

The script uses the Python port of Material Color Utilities (`materialyoucolor`) with the 2021 spec, the same algorithm and spec Flutter uses. It builds a `DynamicScheme` from custom palettes and prints every non-deprecated `ColorScheme` field, from `primary` through `surfaceTint`, as Dart. `design/theme/README.md` explains how to rerun it, in the same way `design/icon/README.md` does.

Palettes (HCT):

| Palette | Light | Dark |
| --- | --- | --- |
| Source and primary | `#1B2638`: hue 261, chroma 18 | same |
| Secondary | hue 261, chroma 6 | same |
| Tertiary | hue 321, chroma 24 | same |
| Neutral | hue 80, chroma 2 (warm paper) | hue 261, chroma 4 (ink graphite) |
| Neutral variant | hue 80, chroma 4 | hue 261, chroma 6 |
| Error | hue 25, chroma 84 (Material default) | same |

Variant: fidelity, so the primary roles follow the source's own tone and `primaryContainer` is the icon ink itself.

Fidelity picks text on containers (`onPrimaryContainer`, `onSecondaryContainer`, `onTertiaryContainer`, `onErrorContainer`) at the lowest contrast it allows, about 4.5:1. On the phone, the label of a selected segment or chip came out fainter than unselected labels. The generator therefore takes these four roles from tone 10 or 90 of their palette, whichever is farther from the container, as Material 3's standard schemes do (about 7:1).

The result checked in the preview:

| Role | Light | Dark |
| --- | --- | --- |
| `surface` | `#FFF8F4` | `#121316` |
| `surfaceContainer` | `#F3EDE8` | `#1E2023` |
| `primary` | `#061122` | `#BCC7DF` |
| `primaryContainer` | `#1B2638` | `#1B2638` |
| `secondaryContainer` | `#DFDFE6` | `#47494E` |

Alternatives considered:
- `ColorScheme.fromSeed(seedColor: ink, dynamicSchemeVariant: fidelity)`: the neutrals would follow the ink hue in both themes and could not be warm in the light theme. Overriding the surfaces with `copyWith` would mix two sources for about fifteen roles.
- Building the `DynamicScheme` at runtime from `material_color_utilities`: no generated file, but it adds a direct dependency on a package that Flutter pins, and needs a hand-written mapping of about fifty roles into `ColorScheme`. Constants are simpler to review and cannot drift with a Flutter upgrade.

The neutral hue of the light theme is 80, not the hue of the icon's own paper color `#F7F6F1` (hue 142). At hue 142 the surfaces lean green, which is what this change removes.

### Icon: change colors, not geometry

In `gen.py` the background becomes a flat ink `#1B2638` with the existing radial highlight, and the dark leaf's default color becomes `#3A5FBD`. The light leaf stays `#F7F6F1`. The leaf paths, glyph center and scales stay the same, so the safe-zone fit of the adaptive icon is unchanged. The monochrome layer is still both leaves in black, and the themed icon does not change.

The vector `ic_launcher_background.xml` gets two paths: a solid ink fill and a radial-gradient highlight with the same center (20%, 15%), radius (80%) and opacity (18% white to 0) as the SVG. Adaptive icons need API 26, and vector gradients work from API 24, so the highlight works wherever this layer is used. Today the vector layer has no highlight and the PNGs do; after this change they match.

Alternative considered: keep a diagonal gradient from ink to blue. It changes less, but the user chose the flat "Night" look in the preview.

## Risks / Trade-offs

- [In the light theme the accent `#061122` is almost as dark as body text `#1E1B17`, so text buttons and links can look like plain text.] → Interactive elements keep their shapes: filled buttons, outlines, the switch track and the navigation pill. Check text buttons on a device; if they blur into body text, rerun the generator with the primary palette's chroma raised a little, not a different hue.
- [On a dark wallpaper an ink icon has less contrast against the background than the old gradient.] → The light leaf and the highlight keep the icon's outline visible. The device check covers a dark wallpaper.
- [Launchers cache icons, so the old icon may show for a while after the update.] → No action. It refreshes on the launcher's next icon reload or a reboot.
- [The generated `theme.dart` can fall behind if someone edits the colors by hand.] → The file header says it is generated and names the script.

## Migration Plan

No data changes. The app update replaces the theme and the icon. Rolling back is a revert of the commit.
